Structure deduction algorithm
=============================

Input:

* The input file, treated as a sequence of characters (Unicode code
  points).

* A language-specific tokenization procedure.

* Language-specific delimiter pairing rules.

Output:

* A token tree that heuristically describes the hierarchical structure
  of the input.

    A token is a contiguous sequence of characters.  The tokens
    partition the input file, such that their concatenation yields the
    original input file.

    A token tree node is either a token or a group.  A group is a
    sequence of child nodes.  Left-to-right traversal of the tree yields
    the original sequence of tokens.


Phase 1: Tokenization
---------------------

The tokenization phase partitions the input into tokens.  The exact
procedure is a parameter that can be tailored to the input language
(e.g., C++ vs. Python).

The most important tokens are delimiters such as braces and parentheses,
as these are treated specially by the deduction algorithm.

Other tokens may include string literals, comments, preprocessor
directives, other kinds of literals, identifiers, etc.

For now at least, the tacit expectation is that linguistically
insignificant whitespace is included with its following non-whitespace
token.

Definition: For every token, its "line indentation" is the number of
leading spaces or tabs (for now, we treat them as equivalent for
simplicity) on its line.  Consequently, all tokens on a given line have
the same line indentation.  The line indentation of a group is the line
indentation of its leftmost token.


Phase 2: Grouping by delimiters
-------------------------------

The delimiter phase walks the token sequence, maintaining a stack of
unmatched opening delimiter tokens.  When a closing delimiter is
encountered, if the top of the stack is the corresponding opening
delimiter, then a new group node is created that has the delimiter
tokens at either end and the nodes (including previously created
delimiter groups) describing the enclosed text between them.

If the top of the stack does not correspond, then we search the stack
(in top down order) for an opening delimiter whose line indentation is
the same as that of the closing delimiter.  If one is found, then we pop
all intervening opening delimiters (hence, they will not be the start of
any group) and form a new group with the found opening delimiter.
Otherwise, the closing delimiter is skipped, hence treated as a
non-delimiter token.


Phase 3: Grouping lines
-----------------------

Every node that is the first on its line (its leftmost token is the
first on its line) is grouped with the next sibling node that is last on
its line (its rightmost token is the last on its line) and all
intervening nodes, if one exists.  This will group ordinary one-line
statements together, as well as multi-line function definitions (if the
body is enclosed by a delimiter).


Phase 4: Grouping by indentation
--------------------------------

For every node that is the first on its line, group it with all
following siblings up to but not including the next sibling that is
first on its line and has equal or less line indentation.  When looking
for the end (one past the end) sibling, ignore (accumulate into the
group) tokens corresponding to blank lines (if such are created by
tokenization).


Phase 5: Grouping paragraphs
----------------------------

A "paragraph" is a sequence of nodes that are all first on their line,
have the same line indentation, and do not have any intervening blank
lines.  Group all paragraphs.


Phase 6: Collapsing redundant groups
------------------------------------

Any group that only has one child is replaced by that child.
Consequently, afterward, every group will have at least two children.
(Empty groups are never created.)



Examples
========

In these example outputs, the token tree is denoted by enclosing groups
in brackets and tokens as quoted strings.  Quoted strings use C-style
escape rules to denote embedded quotes, etc.  To reduce uninteresting
clutter, some of the quoted strings combine multiple tokens that would
be separated in the real tree.


Input 1: C++ Hello World

  #include <iostream>        // std::cout

  int main(int argc, char **argv)
  {
    std::cout << "Hello\n";
    return 0;
  }

Output 1:

  [
    [
      "#include <iostream>"
      "        // std::cout"
    ]
    [
      [
        "\n\nint main"
        [
          "(int argc, char **argv)"
        ]
      ]
      [
        "\n{"
        [
          "\n  std::cout << \"Hello\\n\";"
        ]
        "\n}"
      ]
      "\n"
    ]
  ]

      return false;

    // What is its syntactic parent?

      getNamedParentDeclOpt_templateAdjustment(dn.m_decl);
    if (!parent) {
      // The parent is the TU.
      return true;
    }

    return true;

Input 3: Python function

  def topo_sort_sccs(
    graph: Dict[str, List[str]], sccs: List[List[str]]
  ) -> List[List[str]]:
    """Topologically sort SCCs."""

    # Map from a node to the index in `sccs` where that node is found.
    # Assumes that each node appears in exactly one SCC.
    node_to_scc: Dict[str, int] = {}
    for i, comp in enumerate(sccs):
      for n in comp:
        node_to_scc[n] = i
